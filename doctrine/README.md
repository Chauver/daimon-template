# doctrine/ — le « pourquoi » de la méthode (générée pour TON sport)

À l'onboarding, Claude mène une recherche approfondie (littérature récente) sur ton sport et
ton profil, puis écrit :
- `methodologie.md` — la base de réflexion sourcée, recommandations taguées
  ✅ vérifié / 🟡 à confirmer / ❌ réfuté (n'appuyer une proposition que sur du ✅, ou 🟡 en le disant)
- `banque_evidence.jsonl` — une affirmation par ligne : {"id","theme","claim","sources":[…],
  "status":"verifie|a_confirmer|refute","note"} — append-only, requêtable via `banque.py`
- `regles_programmation.md` — planification : horizons macro/méso/micro, mésocycles,
  plafonds, calendrier de tests
- `regles_seances.md` — construction des séances : échauffement/retour au calme,
  pilotage par bande, protocoles de tests, check-list avant push

La doctrine du Daïmon d'origine (triathlon longue distance) ne se copie pas : chaque athlète
mérite la sienne.
